# Автоматический отчёт по ошибочной и исправленной версии СРО

Отчёт появляется **в терминале после обычного запуска тестов**:

```bash
npm run test:sro7
npm run test:sro8
npm run test:sro9
```

Работает также `python -m pytest sro8`, запуск всех тестов через `npm test`
и запуск тестов в VS Code. Для СРО 7 сохранён `unittest discover`.

Для каждого СРО выводятся имя файла, имя теста и функции, требование,
реальный traceback с ожидаемым и фактическим значениями, причина и исправление.
Одинаковая проверка выполняется против обоих вариантов:

```text
ОШИБОЧНЫЙ — 01_buggy.py
FAILED test_line_total — line_total(2000, 3)
  assert 2003 == 6000
  Причина: Цена и количество складываются.

ИСПРАВЛЕННЫЙ — 02_fixed.py
PASSED test_line_total — line_total(2000, 3)
```

Это реальные результаты отдельных процессов pytest. Существующие тесты,
подтверждающие известную ошибку, могут пройти: например, проверка, что исходная
функция выдаёт неверное значение. В дополнительном сравнении обе версии
проверяются на **правильный результат**, поэтому у ошибочной версии виден FAILED.

Успешное сравнение требует воспроизвести исходную ошибку и пройти все проверки
исправленного варианта. Непройденный или пропущенный исправленный тест,
ошибка сбора, зависание либо различающиеся наборы проверок дают общий exit code 1.
Исходный ненулевой код основного запуска сохраняется.
При сборе списка тестов (`--collect-only`) сравнения не запускаются.

Реализация: [sro_pytest.py](sro_pytest.py) подключён через
[корневой conftest.py](../conftest.py). Каждый выбранный СРО определяется по
своему [comparison.json](../sro8/comparison.json). JUnit, журналы и фактические
результаты сравнения сохраняются в `results/` соответствующего СРО.

## Подключение следующего СРО

Добавьте в каталог работы `comparison.json` по образцу:

```json
{
  "before": "examples/contract_probe.py",
  "after": "examples/contract_probe.py",
  "before_label": "01_buggy.py",
  "after_label": "02_fixed.py",
  "checks": {
    "test_calculation": {
      "function": "calculation(2, 3)",
      "expected": "6",
      "cause": "Объяснение исходной ошибки.",
      "fix": "Описание исправления."
    }
  }
}
```

В `examples/contract_probe.py` напишите одинаковые проверки правильного результата.
Переменная окружения `QA_SRO_VARIANT` равна `before` или `after`; по ней выбирается
проверяемый модуль. Полный пример: [contract_probe.py](../sro8/examples/contract_probe.py).
Имя файла не должно начинаться с `test_`, чтобы сравнение запускалось отдельно.
Количество и имена проверок в обеих версиях должны совпадать.

Если у СРО собственный конфигурационный файл pytest, добавьте в его `conftest.py`:

```python
from scripts.sro_pytest import pytest_configure as pytest_configure
```

В локальном pytest config задайте `pythonpath = ["..", "../backend"]`, как в
[конфигурации СРО 8](../sro8/pyproject.toml). Для включения следующего СРО
в общий запуск добавьте его каталог в `testpaths` корневого pytest config
и в `python.testing.pytestArgs` настроек VS Code.
