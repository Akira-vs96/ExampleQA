# СӨЖ 7. Debugger құралдарын қолдану

Мысал бағдарлама: [01_buggy.py](01_buggy.py). Төмендегі қадамдар VS Code үшін берілген. Скриншоттардың орнына тоқтау нүктелері, орындалатын әрекеттер және күтілетін мәндер көрсетілген логикалық алгоритм қолданылады. Жол нөмірлері файлдың қазіргі нұсқасына сәйкес келеді.

## 1. Дебагтың негізгі әдістері

| Әдіс | Сипаттамасы | Осы бағдарламадағы мысал |
| --- | --- | --- |
| Брут-форс | Аралық мәндерді жаппай қарап, логтар немесе debugger арқылы қатенің орнын іздеу. | Циклдің әр айналымында `current` пен `largest` мәндерін тексеру. |
| Индукция | Бірнеше нақты бақылаудан жалпы қорытынды шығару. | `-8`, `-3`, `-5` сандарының ешқайсысы `largest = 0` мәнін өзгертпейді. Осы бақылаулардан бастапқы нөл теріс сандар тізіміне жарамайды деген болжам жасалады. |
| Дедукция | Бағдарлама ережелері мен болжамнан нақты тексерілетін нәтиже шығару. | Егер пайызды `100`-ге бөлу ұмытылса, `1000 * 20` жеңілдігі `20000` болады. Watch арқылы осы болжамды тексеруге болады. |
| Қарсы бағытта жылжу | Қате нәтижеден бастап, оны тудырған есептеулер мен бастапқы мәндерге қарай талдау. | Қате баға `-19000` → `price - discount` → `discount = 20000` → `price * percent` формуласында `/ 100` жоқ. |

Қарсы бағытта жылжу — себепті нәтижеден іздеу әдісі. Ол debugger бағдарламаны уақыт бойынша кері орындайды дегенді білдірмейді.

## 2. Құралдардың қызметі

| Құрал | Қызметі | VS Code пернесі |
| --- | --- | --- |
| Breakpoint | Белгіленген жол орындалмас бұрын бағдарламаны тоқтатады. | Жол нөмірінің сол жағын басу немесе `F9` |
| Conditional Breakpoint | Берілген шарт ақиқат болғанда ғана тоқтатады. | Тоқтау нүктесін оң жақ батырмамен басу → **Edit Breakpoint…** → **Expression** |
| Step Into | Ағымдағы жолдағы шақырылатын функцияның ішіне кіреді. | `F11` |
| Step Over | Ағымдағы жолды орындайды. Жолдағы функция шақыруын ішіне кірмей орындайды. | `F10` |
| Step Out | Ағымдағы функцияның қалған бөлігін орындап, оны шақырған кодқа қайтарады. | `Shift+F11` |
| Variable Watching | Айнымалылар мен өрнектердің мәндерін әр тоқтаған сайын көрсетеді. | **Run and Debug → WATCH → +** |

**Ескерту:** debugger белгілеп тұрған жол әлі орындалмаған болады. Step Over жолды аттап кетпейді: оны орындайды. Step Out функцияны тоқтатпайды: қалған кодын орындайды. Осы әрекеттер кезінде басқа белсенді breakpoint немесе exception болса, орындау ертерек тоқтауы мүмкін.

## 3. Step Into, Step Over және Step Out: жеңілдікті тексеру

### Дайындық

1. VS Code ішінде [01_buggy.py](01_buggy.py) файлын ашыңыз. Python және Python Debugger кеңейтімдері орнатылған болуы керек.
2. Алғашқы жаттығу үшін басқа тоқтау нүктелерін уақытша өшіріңіз.
3. **26-жолдың** сол жақ жиегін басып, breakpoint қойыңыз:

   ```python
   print("Қате нұсқа: жеңілдіктен кейінгі баға:", final_price(1000, 20))
   ```

4. `F5` басыңыз. Конфигурацияны таңдау қажет болса, **Python Debugger → Python File** таңдаңыз. Жобадағы **Python Debugger: Current File** конфигурациясын да қолдануға болады; бұл кезде ашық файл осы мысал болуы керек.

### Қадамдық алгоритм

| Қадам | Әрекет | Не болады? |
| --- | --- | --- |
| 1 | 26-жолда тоқтағаннан кейін `F11` басыңыз. | Step Into арқылы `final_price(1000, 20)` функциясына кіріп, 11-жолдағы есептеуге жетесіз. |
| 2 | **VARIABLES → Locals** бөлімін қараңыз. | `price = 1000`, `percent = 20`. `discount` әлі есептелмеген. |
| 3 | `F10` басыңыз. | 11-жолдағы `discount = price * percent` орындалады. Келесі тоқтау орны — 12-жол. |
| 4 | Variables немесе Watch ішінен `discount` мәнін қараңыз. | Формула бойынша `discount = 20000` болуы күтіледі. Дұрыс жеңілдік — `200`. |
| 5 | `Shift+F11` басыңыз. | Step Out арқылы `return price - discount` орындалып, басқару функцияны шақырған кодқа қайтады. Қайтарылатын мән — `-19000`. |
| 6 | Егер debugger шақыру тұрған жолда тоқтаса, `F10` басыңыз. | Сыртқы `print(...)` аяқталып, негізгі бағдарлама келесі жолға өтеді. |

Логикалық тізбек:

```text
26-жол: breakpoint
    ↓ F11 — Step Into
11-жол: price = 1000, percent = 20
    ↓ F10 — Step Over
12-жол: discount = 20000
    ↓ Shift+F11 — Step Out
Шақырған кодқа оралу, функция нәтижесі = -19000
```

Step Over айырмасын көру үшін бағдарламаны қайта іске қосып, 26-жолда `F11` орнына `F10` басыңыз. Ішкі breakpoint жоқ кезде есептеу мен экранға шығару тұтас орындалады; функцияның ішкі жолдарын қадамдап көрмейсіз.

## 4. Variable Watching: айнымалыларды бақылау

1. Жоғарыдағы алгоритммен функция ішіндегі **11-жолға** кіріңіз.
2. Сол жақ панельдегі **Run and Debug → WATCH** бөлімін ашыңыз.
3. **+** батырмасын басып, мына өрнектерді бір-бірден қосыңыз:

   ```python
   price
   percent
   discount
   price * percent / 100
   ```

4. `F10` басып, есептеуден бұрынғы және кейінгі мәндерді салыстырыңыз.

| Watch өрнегі | 11-жол орындалғанға дейін | 11-жол орындалғаннан кейінгі күтілетін мән |
| --- | --- | --- |
| `price` | `1000` | `1000` |
| `percent` | `20` | `20` |
| `discount` | Әлі анықталмаған | `20000` |
| `price * percent / 100` | `200.0` | `200.0` |

Осы салыстыру жеңілдікті есептейтін формуладағы қатені көрсетеді: пайызды жүздік үлеске айналдыру қажет.

**Variables** қолжетімді айнымалыларды автоматты түрде көрсетеді. **Watch** ішіне өзіңіз таңдаған айнымалыны немесе өрнекті енгізесіз. Қадам сайын мәндер қайта есептеледі.

Watch таңдалған **Call Stack** кадрының айнымалыларын қолданады. Функциядан шыққаннан кейін оның жергілікті `price`, `percent`, `discount` айнымалылары қолжетімсіз болуы қалыпты жағдай. Ал функцияға жаңа кіргенде `discount` үшін хабарлама шығуы оның меншіктеу жолы әлі орындалмағанын білдіреді.

## 5. Conditional Breakpoint: циклдің қажетті айналымында тоқтау

Мақсат: барлық айналымда тоқтамай, `current` мәні `-3` болған сәтті қарау.

1. Алдыңғы breakpoint-ті өшіріп, **20-жолға** тоқтау нүктесін қойыңыз:

   ```python
   if current > largest:
   ```

2. Тоқтау нүктесін тінтуірдің оң жақ батырмасымен басыңыз. **Edit Breakpoint… → Expression** өрісіне шартты жазыңыз:

   ```python
   current == -3
   ```

3. `Enter` басып, бағдарламаны `F5` арқылы қайта іске қосыңыз.
4. Бағдарлама шарт ақиқат болған айналымда тоқтайды. Watch ішіне мыналарды қосыңыз:

   ```python
   current
   largest
   current > largest
   ```

5. Код бойынша бұл сәтте `current = -3`, `largest = 0`, ал салыстыру нәтижесі `False` болуы күтіледі.
6. `F10` басыңыз. Шарт жалған болғандықтан, 21-жолдағы меншіктеу орындалмайды, `largest` өзгермейді.

Бұл бақылау бастапқы `largest = 0` мәнінің теріс сандарға жарамайтынын көрсетеді. Кәдімгі breakpoint пен шартты breakpoint айырмасын көру үшін шартты алып тастап, қайта іске қосыңыз: енді 20-жолға келген сайын тоқтайды. Келесі тоқтауға өту үшін `F5` қолданыңыз.

## 6. Бос тізімдегі қатені бақылау

1. Басқа тоқтау нүктелерін өшіріп, **7-жолға** breakpoint қойыңыз.
2. Бағдарламаны қайта іске қосыңыз. Ол `average([])` шақыруы кезінде тоқтайды.
3. Watch ішіне `numbers`, `sum(numbers)` және `len(numbers)` қосыңыз.
4. Код бойынша күтілетін мәндер: `[]`, `0` және `0`. Бөлімнің нөл екенін жол орындалмай тұрып байқауға болады.
5. `F10` басқанда нөлге бөлу әрекеті орындалып, `ZeroDivisionError` пайда болады. Debugger баптауына қарай exception жолында тоқтайды немесе қате терминалда көрсетіледі.

Осылайша, тоқтау нүктесі қатенің алдындағы күйді көруге, Step әрекеттері орындалу ретін түсінуге, ал Watch қатеге әкелетін мәндерді бақылауға көмектеседі.
